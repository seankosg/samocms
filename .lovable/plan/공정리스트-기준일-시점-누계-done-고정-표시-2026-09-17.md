# 공정리스트 — 기준일 시점 누계(Done) 고정 표시

## 요청 내용 확인

공정리스트에서 기준일을 과거로 바꿔도 `Done / Total`(K열)과 `실적(%)`은 **항상 최신 값**이 보입니다. 반면 `당일 실적(증분)`(P열)만 기준일 기준으로 계산됩니다. 요청은 "선택한 기준일 시점의 누적 Done"을 보이게 해달라는 것입니다.

## 현재 구조 (확인 결과)

- 공정리스트 표는 `activities` 테이블의 **현재 값**을 그대로 보여줍니다. 기준일은 계획 진도율(선형 재계산)과 당일 증분에만 쓰입니다.
- 날짜별 값은 별도 이력 테이블에 쌓여 있습니다(9/4 ~ 9/17, 항목 약 1,100개). Done 수량·실적%·계획%·총수량이 모두 기록돼 있어 **과거 시점 값 복원은 가능합니다**.
- 기준일은 화면 상단에서 바꾸며, 값이 서버에 저장되는 **전 사용자 공통 설정**입니다.

## 영향도 판단 (문제점)

1. **가장 큰 위험 — 공유 데이터 모델을 바꾸면 안 됨.** 공정리스트가 쓰는 행 데이터는 대시보드·지연·리포트·예측·엑셀이 모두 함께 씁니다. 여기에 과거 값을 덮어쓰면 대시보드 완료 건수, 지연 판정, 리포트 수치가 전부 과거 기준으로 바뀝니다. → 과거 값 적용은 **공정리스트 표 안에서만** 수행합니다.
2. **이력 누락 구간이 있음.** 날짜별 기록 항목 수가 일정하지 않습니다(예: 9/10은 698개, 9/17은 195개). 해당 날짜에 기록이 없는 항목을 공백으로 두면 표가 비어 보입니다. → 「해당 일자 **이하** 가장 최근 기록」을 끌어와 표시하는 방식(carry-forward)으로 처리합니다. 그래도 기록이 전혀 없는(그 날짜 이전에 등록 안 된) 항목은 `—`로 표시하고 개수를 안내합니다.
3. **같은 날 중복 기록.** 하루에 여러 번 업로드된 날은 항목당 기록이 여러 건입니다. → 항목별 **그날 마지막 기록**만 사용합니다.
4. **인라인 수정 충돌.** 과거 시점 표시 중에 셀을 수정하면 현재 값이 바뀌어 화면과 어긋납니다. → 과거 시점 모드에서는 **수정 잠금**.
5. **성능.** 항목 1,100개 × 14일 이력을 전부 내려받으면 느려집니다. → 서버에서 "기준일 시점 최신 1건"만 골라 반환.
6. **기준일이 전역 설정**이라 한 사람이 바꾸면 모두에게 반영됩니다. 이번 기능은 이 동작을 바꾸지 않습니다(별도 요청 시 화면 전용 기준일 검토).

## 제안 방식 — 토글 스위치

공정리스트 상단에 스위치 하나를 둡니다.

- **「기준일 시점 값」 ON** — `Done / Total`, `실적(%)`, `상태`를 선택 기준일 시점 기록으로 표시. 표 상단에 「기준일 YYYY.MM.DD 시점 누계 · 수정 잠금」 안내와, 그 날짜에 기록이 없어 `—`로 표시된 항목 수 표기. 엑셀 내보내기도 같은 값으로.
- **OFF(기본)** — 지금과 동일하게 최신 값 표시.

기준일이 최신 데이터 날짜와 같으면 스위치는 의미가 없으므로 비활성 처리합니다. 대시보드·리포트·지연 등 다른 화면은 **전혀 바뀌지 않습니다**.

## 기술 메모

- 새 서버 함수 `getActivitiesAsOf({ base })`: `activity_snapshots`에서 `snapshot_date <= base` 조건으로 항목별 최신 1건(`DISTINCT ON (item_key) ORDER BY snapshot_date DESC, captured_at DESC`)을 반환하는 SQL 함수(`activities_as_of(_base date)`)를 추가하고 서버 함수로 감쌉니다. 반환: `item_key, snapshot_date, done_quantity, total_quantity, actual_progress`.
- `ScheduleTable`에 `asOf` 상태 추가. ON일 때 표시 직전 단계에서 `itemKeyOf(dept, no, act)`로 스냅샷 맵을 조회해 `done/tot/pc`만 덮어쓴 파생 행 생성(원본 `rows` props는 불변). 정렬·필터·검색·엑셀은 이 파생 행 기준.
- `계획(%)`은 기존처럼 기준일 선형 재계산 값을 유지(이미 시점 일치).
- ON일 때 `canEdit` 경로를 막아 `EditableCell`을 읽기 전용으로.
- 기록 없는 항목은 `done/pc = null` → `—` 표시, `statusOfRow`는 기존 로직 그대로 두되 `pc=null`이면 "예정"으로 나오므로, 이 경우 상태 칸도 `—`로 표기.
