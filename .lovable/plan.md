# 일일 안전 리포트 텔레그램 발송 (Rev.4) — 작업 계획

## 먼저 보고: 지시서와 현재 구조가 충돌하거나 그대로는 안 되는 것

1. **PDF를 화면과 "똑같이" 만들 수는 없습니다.**
   서버는 브라우저가 없는 실행 환경이라 `/today-report` 화면을 그대로 캡처하는 방식(헤드리스 브라우저)을 쓸 수 없습니다.
   대안: 같은 데이터로 **A4 1장 PDF를 서버에서 직접 그리는** 방식으로 만듭니다. 항목·순서·내용(제목, 5개 지표, 팀별/건물별, 위험작업 표, 공통 안전수칙, 서명란)은 화면과 동일하게 맞추되, 미세한 글꼴·간격은 화면과 완전히 같지는 않습니다. 이 전제로 진행합니다.
   한글 PDF를 위해 한글 글꼴 파일이 필요하며, 이 파일은 저장소에 한 번 올려두고 생성 시 불러옵니다.

2. **`app_settings`에 공개(비로그인) 읽기 권한이 아직 없습니다.**
   지시서는 "기존 정책으로 봇이 읽는다"고 되어 있으나 현재는 로그인 사용자만 읽을 수 있습니다. → `safety_tg_%` 키에 한해 공개 읽기를 새로 엽니다(다른 설정 키는 계속 비공개).

3. **저장소(버킷)가 하나도 없습니다.** 공개 읽기 버킷 `safety-reports`를 새로 만듭니다.

4. **생성 시각**: 현재 자동 생성은 현지 03:00 시작, 실패 시 09:00까지 30분 간격입니다. 지시서(04:00 시작, 04:50까지)보다 이미 이르고 재시도 폭이 넓어 **현재 일정을 유지**합니다. 다만 발송 시각(05:00) 전에 확실히 끝나도록 03:00~04:50 구간은 **15분 간격**으로 촘촘히 조정합니다.

5. **텔레그램 실제 발송·재시도·결과 보고는 앱이 하지 않습니다**(지시서 §3.4대로 봇 담당). 앱은 PDF·본문·설정·재발송 신호·결과 표시만 제공합니다.

6. 결과 수신자 **이승한·이정우는 이미 HDEC 회원으로 등록**되어 있어 바로 기본값으로 넣을 수 있습니다.

## 만들 것

### 1) PDF 자동 생성
- 안전 리포트가 한글·영문 **둘 다 저장되는 순간** A4 PDF 2개를 만들어 공개 버킷에 저장(`safety/2026-09-12-ko.pdf`, `-en.pdf`).
- 「다시 분석」 시 PDF도 다시 만들고 파일을 덮어씁니다.
- 저장 후 리포트 행에 PDF 경로와 준비 완료 시각을 기록합니다.

### 2) 설정 화면 「안전리포트 설정」 (관리자 전용, 사이드바 설정 섹션)
- 텔레그램 발송 사용(기본 꺼짐) / 발송 시각 05:00 / 재시도 종료 05:20 / 재시도 간격 5분
- 한글·영문 본문 편집(기본 문구는 지시서 §2.3 그대로, `{date}` 자리표시자, 1,000자 제한)
- 결과 수신자: HDEC 회원 다중 선택(기본 이승한·이정우). 미등록자는 저장 거부.
- 하단에 **최근 발송 결과** 표(날짜·시각·성공·실패·실패 목록·보고 여부)
- **「오늘 리포트 재발송」** 버튼 → 재발송 번호 +1

### 3) 봇 연계
- 공개 조회용 뷰 `v_safety_telegram`: `day`, `pdf_ko_url`, `pdf_en_url`, `cover_ko`, `cover_en`(날짜가 채워진 본문), `ready_at`, `send_seq`.
- 원본 리포트 표는 계속 비공개, 뷰만 공개 읽기.
- 봇이 남기는 `mode='safety'` 기록을 설정 화면 표에서 읽습니다(같은 날짜·회차의 마지막 기록이 최종 상태).

## 기술 메모
- `safety_reports`에 `pdf_ko_path`, `pdf_en_path`, `telegram_ready_at`, `telegram_send_seq` 추가.
- PDF: `pdf-lib` + `@pdf-lib/fontkit`, 한글 글꼴은 버킷에 업로드 후 런타임 fetch + 메모리 캐시. 영문은 내장 표준 글꼴 대신 동일 글꼴 사용해 레이아웃 통일.
- 생성 경로: `src/lib/safety-pdf.server.ts` 신설, `safety-auto.server.ts`와 `analyzeSafety`(다시 분석) 양쪽에서 두 언어 저장 완료 시 호출.
- `app_settings` 공개 읽기: `key LIKE 'safety_tg_%'` 조건의 anon SELECT 정책 + GRANT.
- 뷰는 `security_invoker` 미사용, `GRANT SELECT ON v_safety_telegram TO anon`. (보안 점검기에서 "definer 뷰" 경고가 뜰 수 있으나 의도된 설계입니다.)
- 설정 저장은 기존 `saveManpowerSettings`와 같은 관리자 전용 서버 함수 패턴, 시각 정규화(`9:0` → `09:00`) 재사용.
- cron: `safety-report-auto`를 03:00~04:50 15분 간격 + 05:00~09:00 30분 재시도로 재설정.

## 인수 확인
1. 생성 완료 후 뷰의 오늘 행에 PDF 2개 URL·본문 2개·준비 시각이 채워지고 로그아웃 상태에서 PDF가 열림
2. 공개 키로 뷰 조회 가능, 원본 표 직접 조회는 거부
3. 본문 수정이 다음 생성분에 반영, HDEC 미등록자는 수신자로 저장 불가
4. 재발송 버튼 → 회차 +1
5. 봇의 `mode='safety'` 기록이 설정 화면 표에 표시
