# 사용자 로그인 및 권한 관리 도입

## 목표
아이디(이메일 없음) + 비밀번호로 로그인하고, Admin / User / Guest 세 단계 권한으로 앱 사용을 통제합니다.

## 계정 정책
- 로그인 아이디: 이름 이니셜 + 성 (예: 이희재 → `hjlee`)
- 초기 비밀번호: `Samo@2026!`
- 첫 로그인 시 비밀번호 변경 화면으로 강제 이동, 변경 전에는 앱 사용 불가
- 비밀번호 최소 8자, 입력창에 눈 모양 표시/숨김 토글
- 공개 회원가입 없음 — 계정은 Admin이 생성

## 권한
| 권한 | 가능한 일 |
| --- | --- |
| Admin | 사용자 생성·수정·삭제 + 모든 데이터(공정·T&C·기준일·메모·업로드 이력)의 입력·수정·삭제 |
| User | 모든 화면 + 파일 업로드 + 기준일 변경 (사용자 관리·자료 삭제 불가) |
| Guest | 조회만 (업로드·기준일 변경·메모 저장 불가) |


권한은 향후 등급 추가가 가능한 구조로 저장합니다.

## 담당 공종(업무 영역)
업로드 파일 종류별 담당 업무를 아래처럼 구분합니다.

| 파일 | 담당 업무 |
| --- | --- |
| Arch | 건축 |
| Int (내장) | 건축 |
| Mech | 설비 |
| Elec | 전기 |
| Permit | 공무 (사업지원2팀) |

- User는 자신의 담당 공종 자료만 업로드·수정·삭제할 수 있고, 다른 공종은 조회만 가능합니다.
- Admin은 모든 공종을 제한 없이 다룹니다. Guest는 전 공종 조회만 가능합니다.
- 담당 공종은 사용자별로 저장하며 Admin이 사용자 관리 화면에서 언제든 추가·해제할 수 있습니다(한 사람이 여러 공종 담당 가능).
- 초기 배정: 건축 = 지브릴·황태연, 전기 = 김두현·장건웅, 설비 = 최원진·윤창선·이우영, 공무 = 이희재·어지한·신수영(사업지원2팀 팀장).
- 현장소장(이승한), 각 팀장(김경섭·한용태·이정우), 설계 책임(최규산·김형기)은 전 공종 조회만 부여하고, 필요 시 Admin이 담당을 추가합니다.


## 화면
1. **로그인 화면** — 아이디 / 비밀번호 + 눈 모양 토글. 로그인 성공 시 대시보드로 이동, 비밀번호 미변경자는 변경 화면으로 이동.
2. **비밀번호 변경 화면** — 새 비밀번호 · 확인(최소 8자, 두 입력창 모두 눈 모양 토글).
3. **사용자 관리 화면 (Admin 전용)** — 사용자 목록(이름·아이디·직책·팀·권한·비밀번호 변경 여부), 신규 계정 생성, 정보·권한 수정, 계정 삭제, 비밀번호 초기화(`Samo@2026!`로 되돌리고 다시 강제 변경), 계정 비활성화.
4. **사이드바** — 하단에 로그인 사용자 이름·권한 표시, 로그아웃 버튼, Admin에게만 사용자 관리 메뉴 노출.
5. **기존 화면** — 로그인해야 열람 가능. Guest에게는 업로드 메뉴 숨김, 기준일 설정 버튼과 T&C 메모 저장 비활성화. User에게는 담당이 아닌 공종의 업로드·수정·삭제 버튼이 비활성화되고, 업로드 시 담당 외 파일이면 안내 메시지와 함께 거부합니다.

## 기술 메모
- 인증은 Lovable Cloud 인증 사용. 이메일 없이 쓰기 위해 아이디로부터 고정 내부 주소(`<id>@samo.local`)를 만들어 인증에 사용하고, 화면에서는 아이디만 노출합니다. 이메일 발송이 불가하므로 이메일 기반 비밀번호 찾기는 제공하지 않고, Admin이 초기화합니다. 가입 즉시 사용 가능하도록 이메일 확인은 자동 처리로 설정합니다.
- 신규 테이블
  - `profiles` (id = 인증 사용자 id, username unique, full_name, position, team, must_change_password, is_active)
  - `app_role` enum (`admin` | `user` | `guest`) + `user_roles` 테이블 (역할은 프로필과 분리 저장)
  - `has_role(uuid, app_role)` security definer 함수, RLS 정책 및 GRANT 포함
  - 본인 프로필 조회/수정, Admin 전체 조회·수정 정책
- 기존 공개 읽기 정책(`activities`, `tc_items` 등)은 로그인 사용자 전용으로 좁힙니다. 서버 함수의 데이터 조회는 로그인 토큰 기반으로 전환합니다.
- 쓰기 서버 함수(`importActivities`, `importTcItems`, `setBaselineDate`, `saveTcMemo`, `recordScheduleBatch`)에 인증 미들웨어와 권한 검사를 추가합니다: Guest 거부, User는 담당 공종만 허용, Admin은 전체 허용.
- 담당 공종은 `user_disciplines` 테이블(사용자 + 공종)로 저장하고, `can_edit_discipline(uuid, text)` 함수로 서버·RLS 양쪽에서 동일하게 검사합니다. 파일명(Arch/Int/Mech/Elec/Permit) → 공종 매핑은 업로드 판별 로직과 공유합니다.
- Admin 전용 데이터 관리 기능을 추가합니다: 공정·T&C 행의 개별 수정과 삭제, 업로드 배치·스냅샷 삭제, 공종 데이터 전체 삭제. 모든 삭제는 확인 대화상자를 거치고 서버에서 권한을 다시 검사합니다.


- 라우트는 `src/routes/_authenticated/` 하위로 이동(경로 주소는 그대로 유지), `/auth` 로그인과 `/auth/change-password`는 공개 라우트.
- 초기 17개 계정(명부 16 + admin)은 관리자 전용 일괄 생성 서버 함수로 생성하고, 프로필·권한·비밀번호 변경 플래그를 함께 기록합니다.
