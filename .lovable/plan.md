# 기준일 기반 계획 진도율 재계산

앱에서 기준일을 바꾸면 계획 진도율이 즉시 다시 계산되어 시뮬레이션이 가능하도록 만듭니다. 실적 진도율은 엑셀 원문값 그대로 유지합니다.

## 1. 기준일 자동 인식 개선

- 업로드된 엑셀 파일에서 기준일을 두 곳에서 읽습니다.
  - 시트 2행의 「기준일」 셀 값 (예: 2026-09-07)
  - 파일명의 날짜 (예: `..._20260907_rev.1_Arch.xlsx`)
  - 두 값이 다르면 시트 값을 우선하고, 시트에 없으면 파일명 값을 사용합니다.
- 여러 공종 파일의 기준일이 섞여 있으면 **가장 빠른 날짜**를 앱 기준일로 삼습니다. (현재는 가장 늦은 날짜를 쓰고 있어 이를 변경)
- 기준일 설정 팝오버의 「파일 기준값」과 「파일 기준으로 되돌리기」도 같은 규칙(최소 날짜)을 따릅니다.
- 각 파일의 기준일은 지금처럼 업로드 이력에 파일별로 표시됩니다.

## 2. 계획 진도율 재계산 규칙

각 공정 항목의 시작일·종료일과 기준일을 비교해 선형(일수 비례)으로 계산합니다.

```text
기준일 < 시작일            → 0%
기준일 >= 종료일           → 100%
그 사이                    → (기준일 - 시작일) / (종료일 - 시작일)
시작일 = 종료일 인 경우     → 기준일 >= 그 날짜면 100%, 아니면 0%
시작일 또는 종료일 없음     → 엑셀 원문 계획% 사용
```

- 실적 진도율은 변경 없음(엑셀 원문값).
- 지연 판정(실적 < 계획), 평균 계획%, 차이(%p), 상태색(완료/진행/예정/지연)은 모두 재계산된 계획%를 기준으로 동작합니다.
- 화면에서는 원문 계획%를 노출하지 않고 재계산값만 표시합니다(DB의 원문값은 그대로 보존).

## 3. 반영 화면

- **대시보드**: 계획 대비 실적, 공종별 계획/실적/차이, 지연 건수, 마일스톤 카드
- **공정리스트**: 계획(%) 컬럼과 진척 바, 지연 필터·정렬
- **지연 리스트**: 지연 대상 산정과 평균 격차
- **네트워크**: 노드 계획선, 평균 계획%, 지연 표시, 상세 패널
- **통합 엑셀 내보내기**: 계획(%)은 기준일 기준 재계산값으로 출력하고, 파일명은 현재 기준일을 사용
- T&C는 기존 동작(단계 계획일 ≤ 기준일)을 그대로 유지

기준일을 바꾸면 위 화면들이 즉시 다시 계산되므로, 예를 들어 기준일을 2주 뒤로 옮겨 "그때까지 계획 대비 어디가 밀리는지" 시뮬레이션할 수 있습니다.

## 기술 메모

- `src/lib/schedule-model.ts`: `Row`에 `plRaw`(원문) 유지, `planAt(row, base)` 선형 계산 함수 추가. `isLate`, `stOf`, `avgOf`, `statusOfRow`가 기준일을 인자로 받도록 시그니처 변경.
- 기준일 계산 결과를 `useProject()`에서 한 번 적용한 파생 행(`rows`)으로 제공해 각 화면은 수정 최소화.
- `src/lib/import-schedule.ts`: 시트 상단 「기준일」 셀 스캔 + 파일명 `YYYYMMDD` 파싱 → `file_date`.
- `src/lib/activities.functions.ts` / `project.functions.ts`: 배치 `file_date` 저장 로직에 위 값 사용.
- `src/components/app-shell.tsx`: 자동 기준값을 `sort()[0]`(최소)로 변경.
- `src/lib/network-model.ts`, `src/components/schedule-table.tsx`, `src/routes/dashboard.tsx`, `src/routes/delays.tsx`: 재계산된 `pl` 사용으로 전환.
- DB 스키마 변경 없음.
