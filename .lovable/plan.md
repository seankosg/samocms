# 공종별 진행도 예측선 (계획 대비 예측 완료일)

대시보드 하단, 기존 "진도 추이 · 일일 진도율" 표 아래에 **공종별 예측 그래프** 카드를 새로 추가합니다.
지난 스냅샷 기록으로 최근 진행 속도를 계산해 앞으로의 실적 곡선을 연장하고, 계획 곡선과 나란히 보여줍니다.

## 무엇이 보이나

- 가로축: 첫 기록일 ~ 계획 종료일(또는 예측 완료일 중 더 늦은 날)
- 세로축: 진도율 0~100%
- 선 3개
  - **실적(실선, 진한 파랑)**: 지금까지 쌓인 스냅샷 기록
  - **예측(점선, 파랑)**: 오늘 이후 구간만, 최근 속도로 연장
  - **계획(실선, 회색)**: 각 공정의 시작~종료일 기준으로 매일 계산한 계획 곡선(미래 포함)
- 기준일 세로선 + "오늘" 라벨
- **완료일 마커 2개를 나란히 비교 표시**
  - 계획 완료일: 회색 세로선 + "계획 완료 YYYY.MM.DD" 라벨
  - 예측 완료일: 파란 점선 세로선 + "예측 완료 YYYY.MM.DD" 라벨
  - 두 완료일 사이에 **"선행 N일"(초록) 또는 "지연 N일"(붉은색) 배지**를 붙여 차이가 바로 읽히게 함
- 예측이 계획보다 늦어지는 구간은 **연한 붉은 음영**, 빠르면 **연한 초록 음영**

## 카드 상단 요약 (공종 선택 탭 아래)

공종 탭(전체 / 건축 / 전기 / 기계 / 내장 / 인허가)으로 전환하며, 선택 공종에 대해:

- 현재 실적 %, 계획 %, 격차 %p
- 최근 진행 속도 (%p/일, 계산에 쓴 기록 구간 일수 표기)
- **예측 완료일** 과 계획 종료일 대비 **±N일**
- 속도가 0 이하라 완료 예측이 불가하면 "현재 속도로는 완료 예측 불가"로 표시

공종 요약 표도 함께 두어 5개 공종의 속도·예측 완료일·지연일수를 한눈에 비교할 수 있게 합니다. 표의 각 공종 행을 누르면 해당 공종 공정 목록으로 이동합니다.

## 시인성 설계

- 그래프 높이 260px(모바일 220px), 가로는 카드 폭에 맞춤 · 좁으면 가로 스크롤
- 색은 모두 디자인 토큰 사용(실적=primary, 계획=muted-foreground, 지연=destructive, 선행=chart 계열) — 다크 모드에서도 동일하게 읽힘
- 예측 구간은 점선 + 음영으로 "추정값"임이 한눈에 구분되게 함
- 격자선은 20% 간격 가로선만, 날짜 라벨은 겹치지 않도록 자동 솎아냄
- 마우스를 올리면 그 날짜의 계획/실적(또는 예측) 값과 차이를 툴팁으로 표시
- 범례는 그래프 위에 한 줄, 점선·실선 모양 그대로 표시
- 기록이 2개 미만이면 그래프 대신 "예측에 필요한 기록이 부족합니다" 안내

## 계산 방식

- **속도**: 최근 최대 14일치 스냅샷의 실적값에 최소자승 직선을 맞춰 하루당 증가율(%p/일)을 구함. 기록이 2~3개면 처음과 마지막 값의 단순 평균 속도 사용.
- **예측 완료일**: (100% − 현재 실적) ÷ 속도. 상한 365일, 초과 시 "1년 이상" 표기.
- **계획 곡선**: 기존 `planAt()`을 각 날짜에 적용해 공정 평균으로 산출(현재 대시보드 계획값과 동일 기준).
- 실적은 원문값 그대로 사용하며 어떤 값도 덮어쓰지 않습니다.

## 기술 사항

- 신규 서버 함수 `getProgressForecast` (`src/lib/project.functions.ts`): `activity_snapshots`를 1,000행 단위 페이지네이션으로 **전수** 읽어 `날짜 × 공종` 평균 계획/실적/항목수를 집계해 반환. 행 수 제한 없음.
- 신규 컴포넌트 `src/components/dashboard/forecast-chart.tsx`: 공종 탭 · SVG 라인 차트(외부 차트 라이브러리 없이 직접 그려 점선/음영/축 제어) · 요약 표 · 드릴다운 링크.
- `src/lib/use-project.ts`에 `useProgressForecast` 훅 추가(5분 자동 갱신, 기존 스냅샷 갱신 주기와 동일).
- `src/routes/_authenticated/dashboard.tsx`의 `TrendCard` 아래에 새 카드 배치.
- 미래 계획 곡선은 이미 클라이언트에 있는 `rows`(시작·종료일)로 계산하므로 추가 DB 변경·마이그레이션은 없습니다.
