# 항목별 이력 기록(스냅샷) 도입 계획

## 현재 상태 (확인 결과)

- 공정 데이터(activities 838건)와 T&C 데이터(tc_items 339건)는 **현재 값만** 보관됩니다.
- 파일을 새로 올리면 해당 공종의 기존 행을 **모두 지우고 새로 넣습니다**. 즉 이전 수치는 사라집니다.
- 업로드 이력(import_batches 3건: 파일명·날짜·행수)만 남아 있고, **항목별 과거 진도는 남지 않습니다**.
- 따라서 "이 항목이 8/20에 몇 %였는지", "일일 진도율" 같은 통계는 지금 데이터로는 만들 수 없습니다.

## 목표

업로드할 때마다 항목별 값을 스냅샷으로 쌓아, 날짜별 추이·일일 진도율·지연 발생 시점을 볼 수 있게 합니다.

## 기록 설계

1. 업로드 1회 = 배치 1건. 기존 import_batches를 기준 키로 사용합니다.
2. 공정 이력 테이블(activity_snapshots): 배치, 기준일, 항목 식별키(공종·활동번호·활동명), 계획/실적 진도, 수량, 시작/종료일, 상태.
3. T&C 이력 테이블(tc_snapshots): 배치, 기준일, 항목 식별키(공종·건물·항목·장비), 수량, 단계별 계획/실적일, 완료·잔여, Pass/Fail, 상태.
4. 같은 배치+항목 조합은 1건만 유지(중복 방지). 배치 삭제 시 이력도 함께 정리.
5. 읽기 전용 공개 정책 + 필요한 권한 부여. 쓰기는 서버(업로드 처리)에서만.

## 파생 통계 제공

- 일자별 항목 진도 추이(최근 스냅샷 기준 일 단위 보간 없이 실제 기록 시점 기준).
- 일일/주간 진도율 = (해당 시점 진도 − 직전 시점 진도) ÷ 경과일.
- 공종별·마일스톤별 S-curve(계획 vs 실적) 시계열.
- 지연 항목의 지연 시작 시점 추적.

## 과거 데이터

지금 DB에 있는 값은 현재 1회분만 존재하므로, 적용 시점에 **현재 값을 첫 스냅샷으로 1건 기록**해 기준점으로 삼습니다. 그 이전 시점은 원본 파일을 다시 올려야 복원 가능합니다.

## 화면 (2단계, 승인 시 진행)

- 대시보드에 진도 추이 라인 차트(계획/실적) 추가.
- 공정 List·T&C List에서 항목 클릭 시 해당 항목의 날짜별 기록 보기.
- 스냅샷 시점 선택(예: 지난주 대비 변화량 표시).

## 기술 메모

- 신규 테이블: `public.activity_snapshots`, `public.tc_snapshots` (배치 FK, 항목 식별 컬럼, 값 컬럼, unique 인덱스, 조회 인덱스, GRANT + RLS 공개 SELECT).
- `src/lib/activities.functions.ts`(공정 import)와 `src/lib/project.functions.ts`(T&C import)에서 delete/insert 직후 동일 트랜잭션 흐름으로 스냅샷 insert 추가. 공정 import도 import_batches에 기록하도록 통일.
- 조회용 서버 함수 + `src/lib/use-project.ts`에 React Query 훅 추가.
- 항목 식별키는 안정성을 위해 정규화 문자열(공종|활동번호|활동명, 공종|건물|항목|장비)로 생성.

## 진행 순서

1. 이력 테이블 생성 및 현재 값 초기 스냅샷 기록
2. 업로드 시 자동 스냅샷 저장
3. 추이·일일 진도율 조회 계층
4. 대시보드/리스트 UI 반영
