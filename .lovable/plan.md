# Executive Summary에 진행도 예측 반영

가능합니다. 대시보드 하단 예측(공종별·마일스톤별·T&C)에서 계산한 **예측 완료일과 선행/지연 판정**을 리포트의 AI 요약 입력 자료에 함께 넘겨, Executive Summary가 이를 근거로 전망을 언급하도록 합니다.

## 요약문 구성 변경

현재 4개 문단(진도 / 공종 / 리스크 / 조치)에 **[전망]** 문단 하나를 추가해 총 5개 문단으로 만듭니다.

- **[전망]**: 현재 진행 속도를 그대로 유지할 경우의 전체 예상 완료 시점, 계획 대비 선행·지연 일수, 가장 크게 지연될 것으로 보이는 공종·마일스톤·시운전 단계를 2~3문장으로 정리합니다.
- 기존 4개 문단의 성격과 강조 표기 규칙(핵심 수치 굵게)은 그대로 유지합니다.
- 예측 수치는 제공된 값만 사용하고, 데이터가 부족해 예측이 산출되지 않은 항목은 언급하지 않습니다.

## AI에 전달할 예측 자료

기준일 시점에서 다음을 문장 형태로 정리해 기존 현황 수치 뒤에 덧붙입니다.

- 전체 및 공종별: 현재 실적, 최근 진행 속도, 계획 완료일, 예측 완료일, 선행/지연 일수
- 마일스톤별: 같은 항목(마일스톤 단위)
- T&C: T0·T1·T2·Response 4단계 합산과 MECH·ELEC 팀별 예측 완료일 및 선행/지연 일수

상위 항목 위주로 추려 담아 입력 길이(최대 12,000자) 안에 들어가게 합니다.

## 재생성 동작

요약은 기준일별로 한 번 저장해 재사용합니다. 예측 문단은 새 규칙이므로, 이미 저장된 기준일의 요약에는 자동 반영되지 않습니다. 리포트 화면의 **다시 생성**(관리자) 버튼을 누르면 예측이 포함된 새 요약으로 교체됩니다.

## 기술 사항

- `report.tsx`의 `facts` 계산에 예측 블록 추가. 공종·마일스톤 예측은 기존 `useProgressForecast`(스냅샷 기반) 결과를, T&C 예측은 `src/lib/tc-forecast.ts`의 `buildTcForecast` / `buildTcForecastSummary`를 재사용합니다. 예측 계산 로직은 변경하지 않습니다.
- 예측 요약 문자열 생성은 `src/lib/report-metrics.ts`에 순수 함수(`buildForecastFacts`)로 분리합니다.
- 예측 데이터 로딩이 끝난 뒤 AI 호출이 이루어지도록 `useQuery`의 `enabled` 조건에 예측 로딩 상태를 포함하고, 인쇄 자동 실행 타이밍도 같은 조건을 따르게 합니다.
- `report.functions.ts`의 시스템 프롬프트를 5개 문단(`[진도] [공종] [리스크] [전망] [조치]`)으로 수정하고 글자 수 상한을 700자 → 900자로 상향합니다.
- `report.tsx`의 라벨 색상 맵에 `전망` 톤을 추가합니다.
- 저장 스키마(`exec_summaries`) 변경 없음. 마이그레이션 없음.
