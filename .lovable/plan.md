# 공정표 업로드: "전체 교체" → "업데이트(병합)" 방식 전환 검토

현재는 업로드 시 해당 공종(Arch/Elec/Mech/Int/Permit)의 기존 자료를 모두 삭제하고 파일 내용으로 다시 쓰는 방식입니다. 이를 기존 행을 업데이트하는 방식으로 바꾸려면 아래 항목들을 결정하고 추가로 구현해야 합니다.

## 1. 항목을 "같은 항목"으로 볼 기준 (가장 중요)
- 현재 사실 확인: 공종별로 `공종|Activity No|작업명` 조합이 100% 유일합니다(Arch 252, Elec 115, Int 315, Mech 190, Permit 75 모두 중복 0).
- 결정 필요:
  - Activity No만으로 식별할지, 작업명까지 포함할지. 작업명까지 포함하면 작업명 오타 수정이 "삭제 + 신규"로 잡힙니다.
  - Activity No가 비어 있는 행의 처리 방법(행 순서 기반 임시 키 등).
  - 엑셀 안에 같은 키가 중복될 때 첫 행 채택 / 마지막 행 채택 / 업로드 거절 중 무엇으로 할지.
- 데이터베이스에 이 키에 대한 유일 제약을 추가해야 안전한 업데이트가 가능합니다(현재는 없음).

## 2. 세 가지 변화 유형별 동작 규칙
- 신규(파일에만 있음): 추가.
- 갱신(양쪽에 있음): 어떤 항목을 덮어쓸지 결정.
- 사라짐(DB에만 있음): 즉시 삭제 / 보관 후 숨김(권장) / 그대로 유지 중 선택. 보관을 택하면 "삭제 표시" 항목이 진도율·지연 집계에서 빠지도록 각 화면의 조회 조건을 함께 바꿔야 합니다.

## 3. 앱에서 직접 수정한 값의 보호
- 화면에서 인라인 수정할 수 있는 값(작업명, 수량, 실적, 일정, 선후행 등)과 담당자가 있습니다.
- 결정 필요: 파일 값이 항상 우선인지, 사람이 고친 값이 우선인지, 아니면 "파일 값이 비어 있을 때만 기존 값 유지"인지.
  - 담당자는 이미 "비어 있으면 기존 값 유지"로 동작합니다. 같은 규칙을 다른 열에도 확대할지 정해야 합니다.
  - 사람이 고친 값을 지키려면 "수정된 열" 표시를 따로 기록해야 합니다(추가 작업).

## 4. 기준일·이력 처리
- 지금은 매 업로드가 그 공종 전체의 새 기준일 자료가 됩니다. 업데이트 방식에서는 바뀌지 않은 행의 기준일을 갱신할지 결정해야 합니다.
- 항목별 스냅샷과 일일 증분 집계는 현재 "그 배치에 포함된 행"을 기준으로 남습니다. 바뀐 행만 넣을지, 매번 전체 현황을 남길지 결정해야 합니다(진도율 추이 그래프의 연속성에 직접 영향).
- 지난 날짜 파일을 나중에 올렸을 때(구버전 역주행) 최신 값을 덮지 않도록 파일 기준일·Rev 비교 규칙이 필요합니다.

## 5. 업로드 전 미리보기 확인창 확장
- 지금은 행 수 차이와 신규/사라진 항목 개수만 보여 줍니다.
- 업데이트 방식에서는 신규 / 변경 / 사라짐을 항목 단위로, 그리고 어떤 열이 어떻게 바뀌는지(예: 완료일 9/20 → 9/27)까지 보여 주고 적용 여부를 고르게 하는 것이 안전합니다.

## 6. 권한·안전장치
- 공종별 편집 권한 검사는 그대로 유지합니다.
- 대량 삭제(예: 절반 이상이 사라짐)로 판정되면 경고 후 한 번 더 확인받는 장치가 필요합니다.
- 처리 도중 실패 시 절반만 반영되지 않도록 한 번에 처리(트랜잭션)하는 방식이 필요합니다.

## 7. 성능
- 최대 수천 행 단위이므로 키 기준 일괄 반영(upsert)으로 처리하면 현재와 비슷한 속도를 유지할 수 있습니다.

## 기술 메모
- 수정 대상: `src/lib/activities.functions.ts`의 `importActivities`(삭제+삽입 → 키 기준 upsert + 사라진 행 처리), 미리보기 로직 `src/routes/_authenticated/upload.tsx`.
- 마이그레이션 필요: `activities`에 `(source_file, discipline, activity_no, activity)` 유일 인덱스, 선택 시 `is_deleted`/`deleted_at`, 사람이 수정한 열 표시용 컬럼.
- T&C 업로드(`importTcItems`)도 동일한 전체 교체 구조이므로, 같은 방식으로 맞출지 여부를 함께 결정해야 합니다.

## 확인 부탁드리는 결정 사항
1. 항목 식별 키: Activity No 단독 vs Activity No + 작업명
2. 파일에서 사라진 항목: 삭제 vs 보관 후 숨김
3. 화면에서 직접 고친 값: 파일 우선 vs 사람 수정 우선
4. T&C 업로드도 같이 바꿀지 여부
