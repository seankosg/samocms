# 계획 진도율 집계 방식 수정 (당일 포함 기준)

## 현재 문제

현재 계획 진도율은 "시작일 0%, 종료일 100%" 로 계산합니다.

- 1일 계획(9/11~9/11): 시작=종료라 예외 처리로 9/11에 100% → 정상
- 3일 계획(9/11~9/13): 9/11 = 0%, 9/12 = 50%, 9/13 = 100%

즉 시작일 당일의 작업량이 계획에 전혀 반영되지 않아, 기간 계획은 항상 하루치가 밀려 보입니다.

## 변경할 계산 규칙

작업일수를 "시작일과 종료일을 모두 포함한 일수"로 보고, 기준일까지 지난 일수 비율로 계산합니다.

```text
총일수   = (종료일 - 시작일) + 1
경과일수 = (기준일 - 시작일) + 1

기준일 < 시작일   → 0%
기준일 >= 종료일  → 100%
그 외             → 경과일수 / 총일수
시작일 또는 종료일 없음 → 엑셀 원문 계획% 사용
```

검증 예시

| 계획 기간 | 9/10 | 9/11 | 9/12 | 9/13 |
| --- | --- | --- | --- | --- |
| 9/11~9/11 | 0% | 100% | 100% | 100% |
| 9/11~9/13 | 0% | 33.3% | 66.7% | 100% |
| 9/11~9/14 | 0% | 25% | 50% | 75% (9/14 100%) |

## 영향 범위

계산식 한 곳만 바꾸면 아래가 모두 자동으로 같은 기준을 따릅니다.

- 대시보드 계획 대비 실적, 공종별 계획/실적/차이, 지연 건수
- 공정리스트 계획(%) 컬럼·진척 바·지연 필터, 당일계획 증분
- 지연 리스트, 네트워크 계획선·평균 계획%·지연 표시
- 통합/공정 엑셀 내보내기의 계획(%)

실적 진도율(엑셀 원문값)과 T&C 계산 방식은 변경하지 않습니다.

## 기술 메모

- `src/lib/schedule-model.ts`의 `planAt()`만 수정: 일 단위(864e5) 차이로 `(base - s)/86400000 + 1` ÷ `(e - s)/86400000 + 1`, 0~1 클램프. 시작=종료 예외 분기는 새 식에 자연 포함되므로 제거.
- `dailyPlan()`(기준일 계획 − 전일 계획)은 그대로 두면 새 식 기준으로 정확히 하루치가 나옵니다.
- DB 스키마·저장값 변경 없음.
