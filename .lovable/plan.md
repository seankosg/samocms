# NCR Excel 자동 판별 및 Response Status 매핑 수정

## 확인 결과
- 첨부 파일은 `Master(NCR+OR+SOR)` 1개 시트, 50개 열, 유효 데이터 100건입니다.
- 기본 13개 열은 현재 매핑과 모두 정확히 일치합니다.
- PS1~PS9의 36개 날짜 열도 각 단계별 `Plan Start → Actual Start → Plan Finish → Actual Finish` 순서로 정확히 일치합니다.
- 기준일은 `2026-09-12`, 문서번호 누락·중복은 없습니다.
- 마지막 50번째 열 `Response Status`는 현재 변환 규칙에서 읽지 않아 저장되지 않습니다.
- 자동 판별에는 두 가지 확인된 문제가 있습니다.
  1. 업로드 화면이 시트 본문을 제외한 방식으로 파일을 먼저 열어 판별 함수가 시트 내용을 읽을 수 없습니다.
  2. 판별 함수는 `Current Stage`와 `PS1S`가 같은 행에 있어야 한다고 가정하지만, 첨부 파일에서는 각각 2행과 3행에 있습니다.
- 현재 상태에서는 이 파일이 NCR로 자동 인식되지 않아 실제 업로드 단계까지 진행되지 않습니다.

## 구현 내용
1. **NCR 자동 판별 정상화**
   - 업로드 확인 단계에서도 시트 본문을 읽도록 파일 열기 방식을 수정합니다.
   - 상단 12행 전체에서 기본 헤더 `Current Stage`와 단계 헤더 `PS1S`를 각각 찾도록 판별 조건을 수정합니다.
   - 시트가 없거나 일부 헤더가 누락된 파일은 오류 없이 다른 파일 유형 판별로 넘어가도록 방어 처리합니다.

2. **Response Status 저장 구조 추가**
   - `ncr_items`에 nullable `response_status` 열을 추가하는 데이터베이스 변경을 적용합니다.
   - 기존 100건에는 영향을 주지 않고 값이 없는 상태로 유지합니다.
   - 로그인 사용자 조회와 관리자 업로드 정책은 기존과 동일하게 유지합니다.

3. **Excel 매핑 연결**
   - 첨부 파일의 50번째 열을 `response_status`로 읽습니다.
   - 업로드 검증 규칙과 서버 입력 검증에 해당 값을 포함합니다.
   - 문서번호 기준 갱신 시 `Response Status`도 파일 값 우선으로 갱신합니다.

4. **목록과 Excel 내보내기 반영**
   - NCR 리스트에 `Response Status` 열을 추가해 업로드 결과를 확인할 수 있게 합니다.
   - NCR Excel 내보내기에도 같은 영문 열 이름으로 포함합니다.
   - 기존 자동 현재단계(`Current Stage`) 산출과는 별도 값으로 유지합니다.

## 가상 검증
- 첨부 파일을 실제 저장하지 않고 현재 변환 함수로 다시 읽어 다음을 확인합니다.
  - NCR 자동 판별 성공
  - 유효 데이터 100건
  - 기본 13열, PS 날짜 36열, Response Status 1열의 위치와 값 일치
  - 기준일 `2026-09-12`
  - 문서번호 누락·중복 0건
- 실제 데이터베이스 업로드 함수는 호출하지 않습니다.
- 공정표와 T&C 파일 자동 판별이 기존대로 유지되는지도 코드 수준에서 함께 확인합니다.

## 별도 데이터 검증 안내
- 헤더 매핑과 별개로 현재 단계 날짜 순서 검사에서 2개 행, 4개 사유가 감지됩니다.
- 수정 후 가상 결과에서 해당 문서번호와 한·영 사유를 명확히 보고하며, 실제 업로드 시에는 기존 규칙대로 그 행만 반려됩니다.
