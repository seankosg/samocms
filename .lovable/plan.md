# 출면 모듈 Rev.3 / Rev.3-1 반영 계획

두 지시서를 현재 앱 상태와 대조했고, 검토 의견 4건에 대한 답변을 반영했습니다. 봇(Apps Script) 작업은 범위에서 제외합니다.

## 검토 결과와 확정 사항

1. **회사·장소 시드는 이미 들어가 있습니다.** 지시서는 "비어 있다"고 했지만 실제로는 회사 16곳·장소 23곳이 지시서와 글자 단위로 동일하게 저장되어 있습니다. → 중복 무시로 다시 넣기만 합니다.
2. **자동 갱신 주기는 현재대로 유지합니다.** 이미 일정 4개가 돌고 있으며 현지 05:30~07:30은 10분, 그 외는 매시 1회입니다.
3. **삭제 규칙은 Rev.3-1을 따릅니다** (기록 0건일 때만 삭제, 이름 변경은 마법사).
4. **시트 가져오기 화면은 기록 원본 이름을 그대로 보여줍니다.** 의도된 동작이므로 안내 한 줄만 넣습니다.

## 1) 데이터베이스

- 회사·장소에 `updated_at` 추가(기본값 현재시각). 마스터·회원 저장 시 항상 갱신합니다.
- 봇(공개 키)이 회사·장소·별칭을 **읽기만** 하도록 권한·정책 추가. 기존 출면 기록·수신 이력·회원의 공개 키 정책은 손대지 않습니다.
- 별칭 표 `manpower_aliases` 신설(종류·별칭·정식 이름·메모).
- 출면 카드 조회 뷰가 읽을 때 별칭을 정식 이름으로 바꿔 보여주도록 수정. 일별 뷰·검증 대조 뷰는 이 뷰를 읽으므로 자동 반영되고, 기록 원본 값은 바뀌지 않습니다.
- 표·열 이름과 `(source, sheet_row)` 고유 제약은 봇이 의존하므로 그대로 유지합니다.

## 2) 새 화면 — 출면 마스터 (관리자 전용)

사이드바 「출면 Manpower」의 관리자 항목에 「출면 마스터」 추가. 탭 세 개.

- **회사 / 장소**: 순서·이름·부가정보·활성·기록 수 표. 추가(앞뒤 공백 제거, 완전 일치 중복 검사), 순서 위·아래 이동 및 직접 입력, 활성 토글(비활성 행 회색), **기록 0건일 때만 삭제** 가능. 그 이름을 쓰는 별칭이나 회원이 있으면 삭제 거부하고 이유를 표시합니다. 「이름 변경」 버튼은 새 이름 추가 → 옛 이름을 별칭 등록 → 옛 이름 비활성 → 회원 소속 갱신을 한 번에 수행합니다. 장소 탭 상단에 "Our Site Office 는 항상 첫 번째" 안내, 두 탭 모두 비활성 처리해도 과거 기록은 그대로 집계된다는 안내를 표시합니다.
- **별칭**: 종류·별칭·정식 이름·메모·해당 기록 수·삭제. 추가 시 "이 이름으로 적힌 기록 N건이 정식 이름으로 합쳐집니다", 삭제 시 "원래 이름으로 되돌아갑니다" 확인. 상단에 **별칭 후보**(기록에는 있지만 마스터·별칭 어디에도 없는 이름 + 건수)와 「별칭으로 등록」 버튼.
- 서버 검증: 정식 이름은 마스터에 존재해야 하고, 활성 마스터 이름은 별칭이 될 수 없으며, 별칭의 별칭은 금지.

## 3) 봇 사용자 화면 수정

- 협력사 칸을 자유 입력에서 **활성 회사 드롭다운**으로 교체, 역할이 HDEC이면 `HDEC` 고정.
- 마스터에 없는 협력사 값을 가진 기존 회원에 ⚠ 표시와 안내 툴팁.
- 추가 창 하단에 "신규 업체는 먼저 출면 마스터에 등록" 안내.

## 4) 출면 현황 표시 보완

- 「마지막 수신」을 저장된 동기화 시각과 실제 기록 수신 시각 중 **더 최근 값**으로 표시(봇 직접 기록도 반영).
- 수신 이력의 방식 값이 봇이 쓰는 값(`bot-submit`, `bot-reconcile`)이어도 화면이 깨지지 않도록 알 수 없는 값은 그대로 표시합니다.
- 시트 가져오기 창에 "비교는 기록에 적힌 원래 이름 기준입니다" 안내 한 줄.

## 범위에서 제외

봇(Apps Script)의 폼 드롭다운·역할 판정·제출 upsert·10분 재조정은 앱 밖 작업이라 만들지 않습니다. 앱은 위의 표·열 이름, 공개 키 읽기 권한, `updated_at` 갱신 약속만 지킵니다.

## 기술 메모

- 마이그레이션 두 개: `0010_manpower_masters`(updated_at, anon GRANT/정책, 재실행 안전 시드), `0011_manpower_aliases`(별칭 표 + `v_manpower_cards` 재정의, `security_invoker = on` 유지).
- 서버 함수는 `src/lib/manpower.functions.ts` 에 `saveManpowerMaster` / `setMasterActive` / `deleteMaster` / `renameMaster` / `saveAlias` / `deleteAlias` / `getMasterUsage` 추가. 모두 `requireSupabaseAuth` + `has_role(admin)` 확인 후 service role 처리, `updated_at = now()`.
- 기록 수·별칭 후보는 `manpower_entries` 의 회사·장소별 집계 RPC 하나로 받아 화면에서 나눠 씁니다.
- 화면은 `src/routes/_authenticated/manpower.masters.tsx` 신설, `admin-gate`·기존 표 스타일·`manpower-i18n.ts` 문구 사전 재사용, 고유 `head()` 지정.
- cron 스케줄은 변경하지 않습니다.
