# 출면 모듈 Rev.3 / Rev.3-1 반영 계획 (검토 결과 포함)

두 지시서를 현재 앱 상태와 대조했습니다. 대부분 그대로 반영 가능하고, **네 가지는 지시서의 전제가 현재 상태와 다릅니다.** 아래 「검토에서 발견한 문제」를 먼저 확인해 주세요.

## 검토에서 발견한 문제

1. **회사·장소 시드는 이미 들어가 있습니다.** 지시서는 "비어 있다"고 하지만 실제로는 회사 16곳, 장소 23곳이 지시서와 **글자 단위로 동일하게** 저장되어 있습니다. 시드는 다시 넣어도 무해하므로 안전장치(중복 무시)만 두고 넘어갑니다.
2. **자동 갱신 주기가 지시서와 다릅니다.** 지시서는 "스케줄이 없다 → 10분 간격 등록"이라고 하지만, 이미 4개 일정이 돌고 있고 주기는 **직전에 직접 지시하신 대로** 현지 05:30~07:30 10분, 그 외 매시 1회입니다. 지시서대로 항상 10분으로 바꾸면 호출량이 6배가 됩니다. **기본은 현재 주기 유지**로 진행하고, 원하시면 전 시간대 10분으로 바꾸겠습니다.
3. **삭제 규칙이 두 문서에서 상반됩니다.** Rev.3은 "이름 수정·삭제 없음", Rev.3-1은 "기록 0건이면 삭제 가능 + 이름 변경 마법사". **나중 문서(Rev.3-1)를 따릅니다.**
4. **별칭은 화면·집계에만 적용됩니다.** 구글 시트 가져오기의 비교(diff)는 기록 원본 이름을 그대로 쓰므로, 별칭을 등록해도 시트 가져오기 화면에는 옛 이름이 보입니다. 지시서가 의도한 동작이지만 혼동 소지가 있어 그 화면에 한 줄 안내를 넣겠습니다.

그 외 나머지 항목(봇용 읽기 권한, 갱신 시각 칸, 마스터 화면, 별칭, 회원 협력사 드롭다운)은 실제로 아직 없어서 새로 만듭니다.

## 1) 데이터베이스

- 회사·장소에 `updated_at` 칸 추가(기본값 현재시각), 저장 시 갱신.
- 봇(공개 키)이 회사·장소·별칭 표를 **읽기만** 하도록 권한·정책 추가. 기존 출면 기록·수신 이력·회원 정책은 손대지 않습니다.
- 별칭 표 `manpower_aliases` 신설(종류·별칭·정식 이름·메모).
- 출면 카드 조회 뷰가 회사·장소 이름을 읽을 때 별칭을 정식 이름으로 바꿔 보여주도록 수정. 일별 뷰·검증 대조 뷰는 이 뷰를 읽으므로 자동 반영됩니다. 기록 원본 값은 절대 바뀌지 않습니다.

## 2) 새 화면 — 출면 마스터 (관리자 전용)

사이드바 「출면 Manpower」의 관리자 항목에 「출면 마스터」 추가. 탭 세 개.

- **회사 / 장소**: 순서·이름·부가정보·활성·기록 수 표. 추가(앞뒤 공백 제거 + 완전 일치 중복 검사), 순서 위·아래 이동 및 직접 입력, 활성 토글(비활성 행 회색), 기록 0건일 때만 삭제 가능. 삭제는 그 이름을 쓰는 별칭·회원이 있으면 거부합니다. 「이름 변경」 버튼은 새 이름 추가 → 옛 이름을 별칭 등록 → 옛 이름 비활성 → 회원 소속 갱신을 한 번에 수행합니다. 장소 탭 상단에 "Our Site Office 는 항상 첫 번째" 안내, 두 탭 모두 비활성 처리 시 과거 기록은 그대로 집계된다는 안내 표시.
- **별칭**: 종류·별칭·정식 이름·메모·해당 기록 수·삭제. 추가 시 "이 이름으로 적힌 기록 N건이 정식 이름으로 합쳐집니다" 확인, 삭제 시 "원래 이름으로 되돌아갑니다" 확인. 상단에 **별칭 후보**(기록에는 있지만 마스터·별칭 어디에도 없는 이름 + 건수) 목록과 「별칭으로 등록」 버튼.
- 검증 규칙(서버): 정식 이름은 마스터에 존재해야 하고, 별칭은 활성 마스터 이름일 수 없으며, 별칭의 별칭은 금지.

## 3) 봇 사용자 화면 수정

- 협력사 칸을 자유 입력에서 **활성 회사 드롭다운**으로 교체, 역할이 HDEC이면 `HDEC` 고정.
- 마스터에 없는 협력사 값을 가진 기존 회원은 ⚠ 표시와 안내 툴팁.
- 추가 창 하단에 "신규 업체는 먼저 출면 마스터에 등록" 안내.

## 4) 자동 동기화 표시

출면 현황 상단의 「마지막 수신」을 저장된 동기화 시각과 실제 기록 수신 시각 중 **더 최근 값**으로 표시(봇 직접 기록도 반영).

## 기술 메모

- 마이그레이션 두 개: `0010_manpower_masters.sql`(updated_at, anon GRANT/정책, 시드 재실행 안전), `0011_manpower_aliases.sql`(별칭 표 + `v_manpower_cards` 재정의). 뷰는 `security_invoker = on` 유지.
- 서버 함수는 `src/lib/manpower.functions.ts` 에 `saveManpowerMaster` / `setMasterActive` / `deleteMaster` / `renameMasterWizard` / `saveAlias` / `deleteAlias` / `getMasterUsage` 추가. 모두 `requireSupabaseAuth` + `has_role(admin)` 확인 후 service role 로 처리.
- 기록 수·별칭 후보는 `manpower_entries` 의 회사·장소별 집계 RPC 하나로 받아 화면에서 나눠 씁니다.
- 화면은 `src/routes/_authenticated/manpower.masters.tsx` 신설, `admin-gate`·기존 표 스타일·`manpower-i18n.ts` 문구 사전 재사용, 고유 `head()` 지정.
- cron 스케줄은 위 2번 결정에 따르며, 기본은 변경하지 않습니다.
