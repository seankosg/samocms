# 출면(Daily Manpower) 모듈 · 1단계 구현 계획

Telegram 봇이 협력사 일일 출면과 HDEC 재집계를 앱 데이터베이스에 직접 기록하고, 앱은 그 자료를 읽어 집계·검증·추이 화면과 봇 사용자 관리를 제공합니다. 앱은 봇이나 구글 시트와 통신하지 않고 같은 데이터만 봅니다.

이번 범위는 지시서의 **1단계 전부**입니다. 2단계 화면(협력사별 통계, KPI, 출면 설정)은 만들지 않되, 나중에 덧붙일 수 있도록 표·집계 함수·차트 구조를 미리 그 형태로 만듭니다.

## 확정된 사항

- 대시보드의 출면 요약 카드는 이번 1단계에 포함합니다.
- 봇 접속 권한은 지시서 §1.5 그대로(공개 키로 기록 허용, 삭제는 전면 차단).
- 화면 문구는 한국어만. 다음 단계의 한/영 토글을 위해 문구는 한 파일에 모아둡니다.

## 1) 저장 구조

새 마이그레이션 `0009_create_manpower.sql` 하나로 다음을 만듭니다. 컬럼명·제약 이름은 봇이 의존하므로 지시서 그대로 씁니다.

- **출면 카드**(`manpower_entries`): 시트 한 행 = 한 건. 협력사 보고/HDEC 재집계 구분, 유효/대체 상태, 회사·보고일·장소·조, 7개 직종 인원과 소계, 제출 시각. 대체된 기록도 지우지 않고 이력으로 남깁니다.
- **봇 사용자**(`manpower_members`): 앱이 원본, 봇이 1분마다 읽어 갑니다.
- **마스터**: 협력사 16곳, 장소 23곳을 순서대로 미리 넣어 둡니다. 공종·건물코드·구역 칸은 비워 두고 다음 단계에서 채웁니다.
- **확장용 빈 표**: 계획 인원, 근무일 달력, 봇 수신 이력.
- **설정값**: 보고 마감 09:00, 주 시작 토요일, 추이 기본 30일.

집계는 저장하지 않고 항상 계산으로 얻습니다. 이를 위해 조회용 뷰 3개(카드 단위 / 일별·회사별 / 협력사-HDEC 대조)를 지시서와 동일한 이름·컬럼으로 만듭니다.

## 2) 화면

사이드바에 **「출면 Manpower」** 그룹을 「데이터」 위에 추가합니다.

### 출면 현황 `/manpower`
- 상단 소형 카드 4개: 총원 · 보고 준수율 · 검증 커버리지 · 미보고 발견. 마지막 봇 수신 시각을 표시하고 30분 이상 끊기면 붉은 배너.
- 블록 1 협력사별 현황 표(주간/연장/야간/계 + 직종별 + HDEC 계 · 차이 · 첫 보고시각, 합계 행, 마감 후 미보고 회사는 회색 "미보고" 행).
- 블록 2 협력사 × 장소 매트릭스(0은 빈칸, 값 없는 열 숨김 토글, 마우스 올리면 조별 분해, 하단 장소 합계).
- 블록 3 직종별 총계(협력사 보고 / HDEC 재집계 나란히) — 이후 일일보고서가 그대로 가져다 쓸 수 있도록 형태 고정.
- 블록 4 오늘의 검증 예외(일치 건 제외).
- 날짜 선택기(기본 오늘, 제다 현지시각), 협력사 보고/HDEC 토글, 엑셀 내보내기.

### 검증 대조 `/manpower/compare`
기간(기본 7일)·판정 칩·회사 필터가 붙은 대조표. 정렬 기본은 HDEC ONLY → 차이 → 미집계 → 일치. 회사별 요약(커버리지·일치율·평균차) 접기/펼치기, 엑셀 내보내기.

### 추이 `/manpower/trend`
기간 프리셋(7/30/90/전체). 차트 3개 — 일일 총원(협력사·HDEC·7일 이동평균, 비근무일 음영, 당일/누적 토글), 회사별 스택 막대(상위 8개사 + 기타, 클릭 시 단일 회사), 직종 구성 스택.

### 봇 사용자 `/manpower/members` (관리자)
이름·소속·역할·활성·메모 인라인 편집과 추가. "역할 변경은 1분 안에 봇에 반영됩니다. Telegram ID 는 봇에 /whoami 를 보내면 확인됩니다." 안내 표시.

### 대시보드 카드
대시보드에 오늘 출면 요약 카드(총원, 보고 준수율 n/N, 검증 커버리지)를 추가하고 클릭 시 `/manpower` 로 이동합니다.

## 3) 앱에서 못 하는 것 (사전 보고)

- **출면 자료 직접 입력·수정·삭제**: 지시서에서 금지한 항목이라 만들지 않습니다. 잘못된 보고는 봇으로 재제출합니다.
- **봇 쪽 동작(시트 연동, /whoami, 재조정 주기)**: 앱 밖의 Apps Script 영역이라 이번 작업에 포함되지 않습니다.
- **인수 확인 §5 중 1·2·3·6번**은 봇이 실제로 기록을 넣어야 확인됩니다. 앱 쪽에서는 같은 상황을 흉내 낸 시험 자료로 화면 동작만 확인하고, 봇 연동 확인은 봇 배포 후 함께 진행합니다.
- **생산성(공수÷진도)** 은 3단계 항목이라 이번엔 계산하지 않되, 연결 고리가 되는 건물코드·공종 칸은 지금 만들어 둡니다.

위 네 가지 외에는 1단계 지시 내용을 빠짐없이 구현합니다.

## 기술 메모

- 마이그레이션 `drizzle/migrations/0009_create_manpower.sql`: enum → 테이블 → GRANT → RLS → 정책 → 인덱스 → 뷰 순. 뷰는 `security_invoker = on` 으로 만들어 기반 테이블 정책이 그대로 적용되게 합니다. 마스터 시드는 마이그레이션 이후 데이터 도구로 삽입합니다.
- `anon` 에는 `manpower_entries`·`manpower_ingest_log` 의 SELECT/INSERT/UPDATE, `manpower_members` 의 SELECT 만 부여. DELETE 정책은 어디에도 만들지 않습니다. `UNIQUE (source, sheet_row)` 는 봇의 upsert 근거이므로 이름 고정.
- 데이터 로딩은 서버 함수 하나 `getManpowerRange(from, to)` (`createServerFn` + `requireSupabaseAuth`)로 통일 — 카드 행 + 마스터 + 달력 + 계획을 함께 반환. 출면 현황은 `from = to`.
- 집계는 전부 `src/lib/manpower-model.ts` 순수 함수(회사·날짜·source 단위 반환): 카드→일별→기간, `isWorkday`(달력 우선, 없으면 금요일 규칙), 이동평균, 준수율, 커버리지·일치율.
- 회원 저장은 `src/lib/manpower.functions.ts` 에서 `has_role(admin)` 확인 후 service role 로 기록.
- 차트는 `ManpowerLineChart` 공용 컴포넌트 하나(series·모드 props)로 만들어 2단계에서 재사용. 기존 `ui/chart.tsx`·`export-dialog`·`column-filter` 재사용, 표는 모바일 가로 스크롤·헤더 고정.
- 문구는 `src/lib/manpower-i18n.ts` 에 ko 사전으로 모아 두어 다음 단계에서 en 만 추가하면 되게 합니다.
- 각 route 에 고유 `head()` 메타 지정.
